# 헤르메스의 신발 AI 활용 기록 (발표용)

> 자세한 원본은 로컬에 있고, 여기에는 발표에서 보여 줄 사례만 정리했다.

| 항목 | 내용 |
|---|---|
| 담당 | 헤르메스의 신발 (팀 공용 SOR 모델러 포함) |
| 사용한 AI | Claude Code (Claude Opus 5.5) |
| AI에게 맡긴 범위 | SOR 모델러·공용 코드 작성, 프로파일 좌표와 조립 수치 초안, 테스트와 렌더링 검증, 문서 초안, Git 작업 |
| 내가 직접 한 범위 | 디자인 방향과 레퍼런스 선정, 문제 지적, 수정 승인, 모델러에서 부츠 부품 5개와 샌들 부품 9개 `.dat` 저장, 샌들 밑창 프로파일 점 3개와 깃털 점 6개 수정 |

## 1. 문제 해결 사례

### 사례 1: 둥글기만 한 앞코 → 샌들로 재설계

| 칸 | 내용 |
|---|---|
| 문제 | 첫 부츠 안의 앞코는 반구를 늘린 모양이라 공처럼 보였다 |
| AI가 한 일 | 샌들 재설계안, 180°만 도는 부분 회전 기능 구현, 부품 9종 초안 |
| 검증 방법 | 네 방향 렌더링, 예전 부품 5개의 `.dat`·`.prof`가 바이트까지 같은지 비교, 테스트 23개 |
| AI의 실수와 수정 | 첫 시안에서 가죽끈이 밑창을 뚫고 발등끈이 떠 있음 → 다른 각도에서 보고 수정 |
| 내가 한 일 | 앞코 문제를 지적하고 새 레퍼런스를 골라 재설계를 결정. 시안 확인 후 진행 승인 |
| 증거 | PR #10 (부분 회전), `docs/items/hermes-shoes.md`와 미리보기 |

### 사례 2: 모델러 "열기 실패"와 덮어쓰기 위험

| 칸 | 내용 |
|---|---|
| 문제 | 모델러에서 `hermes_sole`을 열 수 없었다 |
| AI가 한 일 | 원인 분석: 더블클릭으로 실행하면 작업 폴더가 `Bin/Debug`가 되어 `Models`를 못 찾음. 폴더 자동 찾기와 덮어쓰기 확인 추가 |
| 검증 방법 | `Bin/Debug`에서 실행해 5개 열기·저장, 덮어쓰기 취소와 승인 시험 |
| AI의 실수와 수정 | 처음 만든 모델러는 열기에 실패한 뒤 저장하면 원본을 경고 없이 덮어썼다. 수정 중 줄바꿈 문자 실수로 빌드가 두 번 실패했고 고쳤다 |
| 내가 한 일 | 모델러를 직접 쓰다가 문제를 발견해 알리고 수정을 승인. 고친 모델러로 부품 5개 저장 |
| 증거 | PR #6 |

### 사례 3: 밑창 발끝을 직접 둥글게 수정

| 칸 | 내용 |
|---|---|
| 문제 | AI 초안의 밑창이 조금 각져 보였다 |
| AI가 한 일 | 밑창 프로파일 초안 작성, 수정 후 검사, 전후 비교 렌더링 |
| 검증 방법 | 찌그러진 삼각형 0, 법선 방향 확인, 가죽끈 4개가 좁아진 밑창 안에 들어오는지 폭 계산(여유 0.007~0.019), 전후 비교 이미지 |
| AI의 실수와 수정 | 초안의 발끝이 각져 있었다 → 아래처럼 직접 수정 |
| 내가 한 일 | 밑창이 조금 각져 보여서 모델러에서 1~3번 점을 축 쪽으로 옮겨 발끝을 둥글게 깎고 다시 저장 (폭 0.090→0.073, 0.150→0.133, 0.185→0.180) |
| 증거 | `Models/hermes_footbed.prof`, 수정 전후 비교 이미지 |

### 사례 4: 깃털을 더 날카롭게 수정

| 칸 | 내용 |
|---|---|
| 문제 | 깃털을 더 날카롭게 하고 싶었다 |
| AI가 한 일 | 깃털 프로파일 초안 작성, 수정 결과의 폭과 끝 각도 측정, 다시 고칠 점 안내 |
| 검증 방법 | 첫 수정은 끝 각도가 111.4°로 그대로이고 가운데가 넓어진 것을 측정으로 확인 → 다시 수정한 뒤 끝 각도 91.3°, 위쪽 폭 약 4~6% 감소, 찌그러진 삼각형 0 |
| AI의 실수와 수정 | 처음 안내(4~6번 점을 아래로)로는 끝이 날카로워지지 않았다. 다시 안내할 때도 1번 점의 값을 모델러가 축에 붙여 버리는 값(0.010)으로 잘못 적어 고쳐 안내했다 |
| 내가 한 일 | 측정 결과를 보고 다시 고치기로 하고 모델러에서 1~6번 점을 다시 옮겨 저장. 고치기 전후 화면 캡처 |
| 증거 | `Models/hermes_plume.prof`, 수정 전후 비교 이미지와 모델러 화면 캡처 |

## 2. 미로 기반 (이동·충돌·아이템 배치)

| 항목 | 내용 |
|---|---|
| 사용한 AI | Claude Code (Claude Opus 5.5) |
| AI가 한 일 | 미로 기반 설계안(파일 구성, 지도 글자 형식, 아이템 조립 파일 `.item`, 능력 등록 방식) 제안, `MazeGame/` 코드 작성, 헤르메스·등불 조립표를 `.item`으로 옮김. 게임 흐름에 맞춰 관문(가짜 벽·가시 구덩이·창살)이 있는 고정 지도와 갈 수 있는 곳 검사 도구, 코드로 만든 벽돌·돌바닥·그리스 문양 텍스처, 대쉬(`HermesShoes.cpp`), 분할 4 SOR 단상(`pedestal.prof`, 면 법선·박스 매핑 텍스처·충돌), 나머지 세 능력의 기본 버전(`Lamp.cpp` 가시거리, `ArgosEye.cpp` Q 투시, `AriadneThread.cpp` BFS로 출구까지 붉은 실), 자동 시험과 화면 캡처 |
| 검증 방법 | 지도: 능력이 없을 때 / 눈 / 눈+대쉬일 때 갈 수 있는 곳을 계산해 설계한 순서대로만 열리는지 확인. 실제 게임 코드로 만든 임시 시험 26개: 첫 대화 후 전달, 가짜 벽(투시 없으면 막힘, 투시 중 통과, 안에서 끝나면 되돌림), 가시 구덩이(걸어서 막힘, 대쉬로 통과, 위에서 끝나면 되돌림), 쿨타임, 대쉬로 벽 통과 없음, 등불 가시거리, Q 투시 지속·쿨타임, 실타래 → 출구 → 탈출. 화면 캡처로 텍스처·창살·구덩이·투시 확인 |
| AI의 실수와 수정 | 첫 시험에서 벽면 위치를 잘못 계산해 2개가 실패로 나옴 → 기준을 고쳐 다시 확인. 탈출 화면 글자가 밝은 출구와 겹치고, 좁은 창에서 긴 문장이 사라지는 문제를 화면 캡처에서 발견해 수정. 창살 대화 거리를 1.9로 잡아 앞 칸 가운데(2.0)에서 대화가 안 되는 것을 시험에서 발견 → 2.4로 수정. 창살 너머 미노타우르스가 어둡고 뒤에서 비춰 안 보이는 것을 캡처에서 발견 → 창살 바로 뒤로 옮기고 앞쪽에 횃불 조명 |
| 내가 한 일 | 미로 기반을 직접 맡기로 결정, 설계안 승인. 직접 플레이해 보고 등불 시야, 이동속도, 마우스 감도, 천장 어둠 문제를 지적. 나머지 능력의 기본 코드를 만들기로 결정. 게임 흐름(갇힌 미노타우르스, 유물 수리 후 능력, 메트로베니아식 진행, 가시 구덩이는 대쉬로, 등불·눈 우선, 고정 지도)과 분위기 레퍼런스(벽돌·황색·그리스 로마·황폐함) 제시 |

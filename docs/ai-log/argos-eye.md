# 아르고스의 눈 AI 활용 기록

| 항목 | 내용 |
|---|---|
| 담당 | 아르고스의 눈 |
| 사용한 AI | Claude Code (Claude Opus 5.5 / Claude Fable 5.2) |
| AI에게 맡긴 범위 | 레퍼런스 분석과 부품 구성 제안, SOR 프로파일(`.prof`)과 설계서 작성, 저장소 밖 임시 프로그램으로 조립·검증 |
| 내가 직접 한 범위 | 45° 간격 8방향 레퍼런스 이미지와 디자인 요구사항 작성·제시, VS 2022로 빌드하도록 결정, 구현 방식을 AI 판단에 맡김, SORModeler에서 부품 10개를 직접 열어 `.dat`으로 저장 |

## 1. 문제 해결 사례

### 사례 1: 회전 대칭이 아닌 유물을 SOR로 나누기

| 칸 | 내용 |
|---|---|
| 문제 | 레퍼런스의 금테·작은 눈·공작 깃털은 회전 대칭이 아니라 SOR 하나로 만들 수 없었다. |
| AI가 한 일 | 회전체 10개로 나눴다(받침대, 금띠, 다리, 눈알, 홍채, 동공, 링, 반 바퀴 띠, 금테, 깃털). 비대칭 장식은 같은 메시를 위치·회전·비균등 스케일만 바꿔 재사용했다. 예: 원형 금테 → 아몬드, 방추 → 납작한 깃털. |
| 검증 방법 | 정면·우측·후면·좌측 네 방향 렌더링 ([미리보기](../items/img/argos-eye-preview.png)) |
| AI의 실수와 수정 | 처음 제안에서는 눈알(반지름 0.25)과 링(안쪽 0.29) 사이가 떠 있었다. 옆으로 한 바퀴 도는 링은 정면 홍채를 가렸다. 그래서 눈알을 0.27로 키우고 링 안쪽을 0.262로 줄여 링이 눈알을 붙잡게 했다. 옆 링은 뒤쪽 반 바퀴 띠(SWEEP 180)로 바꿨다. |
| 내가 한 일 | 8방향 레퍼런스와 디자인 요구사항을 제시했다. |
| 증거 | [설계서](../items/argos-eye.md) 2·3절 |

### 사례 2: 부품끼리 겹침·뜸 자동 검사

| 칸 | 내용 |
|---|---|
| 문제 | 부품 30여 개를 조립하면서 뚫고 나오거나 떠 있는 곳을 눈으로만 찾기 어려웠다. |
| AI가 한 일 | 임시 프로그램에서 각 정점이 다른 부품 면의 안쪽에 있는지(면 법선과의 내적 부호)와 부품 간 최소 거리를 계산했다. |
| 검증 방법 | 검사 결과를 의도한 맞물림과 실제 문제로 나누고, 고친 뒤 다시 검사했다. |
| AI의 실수와 수정 | ① 금띠가 받침대에서 0.004 떠 있어서 띠 안쪽을 받침대 속으로 넣었다. ② 깃털 7개가 한 점에서 퍼져 서로 뚫고 지나가서 뿌리를 테를 따라 20°씩 떨어뜨렸다. ③ 처음 검사 코드는 박혀 있는 부품도 "떠 있음"으로 잘못 판정해 수정했다. ④ 깃털이 자기 눈무늬와만 닿아도 붙어 있다고 판정하던 것을 그룹 단위 검사로 고쳤다. 그 결과 실제로 떠 있던 깃털 뿌리를 찾아 테 속으로 옮겼다. |
| 내가 한 일 | (확인 후 작성) |
| 증거 | 설계서 3절 검증 문단 |

### 사례 3: 모델러로 저장한 `.dat` 검증

| 칸 | 내용 |
|---|---|
| 문제 | 모델러에서 저장한 `.dat`이 설계한 프로파일과 정확히 같은 메시인지 확인해야 했다. |
| AI가 한 일 | 10개 `.dat`을 공용 `LoadMesh`로 읽고, 같은 `.prof`를 공용 `BuildSOR`로 다시 만든 결과와 비교했다. |
| 검증 방법 | 정점·법선 최대 차이 1e-6 이하, 삼각형 index 완전 일치, 법선 단위 길이, 면 법선과 정점 법선 방향 일치(CCW)를 확인했다. `.prof`도 처음 설계값 그대로였다. |
| AI의 실수와 수정 | 없음 |
| 내가 한 일 | 모델러에서 `.prof` 10개를 열어 같은 이름으로 `.dat` 저장 |
| 증거 | `Models/argos_*.dat`, 설계서 6절 |
